# Deploying — free hosting on a Hostinger domain

This is a **Node.js app**, not a static site. That matters for one reason:

> **Hostinger's shared/Premium/Business hosting cannot run it.** Those plans serve
> PHP, not long-running Node processes. Only a Hostinger **VPS** could, and that
> isn't free.

So the plan is: **keep the domain at Hostinger, run the app free on Render, and
point one at the other with DNS.** You keep the domain you paid for; the hosting
costs nothing.

Total time: about 25 minutes, most of it waiting for DNS.

---

## Before you start — read this one caveat

Render's free plan **sleeps a service after 15 minutes with no traffic.** The next
visitor then waits roughly **50 seconds** for it to wake up.

For a portfolio, that is a real problem: a recruiter clicks your link, sees a blank
tab for most of a minute, and leaves. Your options, honestly:

| Option | Cost | Cold start |
|---|---|---|
| Render free, accept the sleep | free | ~50s after idle |
| Render free + an uptime pinger every 14 min | free | none in practice |
| Render Starter | ~$7/mo | none |

The pinger works — [cron-job.com](https://cron-job.com) or
[UptimeRobot](https://uptimerobot.com) hitting `https://yourdomain.com/api/health`
every 14 minutes keeps it warm, and 24/7 uptime lands just inside the free tier's
750 instance-hours per month. Be aware it's against the spirit of the free plan and
leaves no headroom. If the site ever starts mattering to your income, the $7 is the
honest answer.

Free tiers change often — check Render's current pricing page before you commit.

## Step 1 — Put the code on GitHub

The local repo is committed and the remote is already configured. You only need to
create the empty repo on GitHub:

1. Open <https://github.com/new?name=swacchokhan.space>
2. Leave it **Public**. Add **no** README, .gitignore or licence — this repo already
   has them, and GitHub adding its own would collide on the first push.
3. Click **Create repository**, then run:

```bash
git push -u origin main
```

Windows opens a browser window to authorise Git the first time.

Your `.env` is git-ignored, so no secrets leave your machine. Verify with
`git ls-files` — the only env file listed should be `.env.example`.

---

## Step 2 — Get a Gmail App Password

**Do this before deploying.** Render's disk is wiped on every restart, so without
SMTP the contact form silently throws messages away. The app will warn you in the
logs, but it won't stop you.

1. Turn on 2-Step Verification: <https://myaccount.google.com/security>
2. Create an App Password: <https://myaccount.google.com/apppasswords>
3. Name it "Portfolio site". Google gives you a 16-character password.
4. Keep that tab open — you need it in the next step.

Use `khanswaccho@gmail.com` as `SMTP_USER` and that 16-character string as
`SMTP_PASS`. It is **not** your normal Gmail password.

---

## Step 3 — Deploy on Render

1. Sign up at <https://render.com> with your GitHub account (free, no card).
2. **New → Blueprint**, pick the `swacchokhan` repo. Render reads
   [`render.yaml`](render.yaml) and fills in almost everything.
3. It will prompt for the values marked `sync: false`:

   | Field | What to enter |
   |---|---|
   | `SMTP_USER` | `khanswaccho@gmail.com` |
   | `SMTP_PASS` | the 16-character App Password |
   | `SITE_ORIGIN` | leave blank for now — you'll set it in step 5 |
   | `GITHUB_TOKEN` | optional, skip it |

4. Click **Apply**. First build takes 2–4 minutes.
5. You get a URL like `https://swacchokhan.onrender.com`. Open it — the whole site
   should work, including the 3D book and the assistant.

`CSRF_SECRET` is generated by Render automatically and stays stable across deploys.

## Step 4 — Point the Hostinger domain at Render

### 4a. Tell Render about the domain

In Render: **your service → Settings → Custom Domains → Add Custom Domain.**

Add **both**:
- `swacchokhan.space` (or whatever your domain is)
- `www.swacchokhan.space`

Render then shows you the exact DNS records to create — **an A record value for the
root domain and a CNAME target for `www`.** Copy those exact values; don't use
numbers from a tutorial, Render's differ per account and change over time.

### 4b. Add the records in Hostinger

1. Log in to **hPanel** → **Domains** → click your domain.
2. Open **DNS / Nameservers** → **DNS records**.
   *(If the domain is using external nameservers, switch it back to Hostinger's
   first: `ns1.dns-parking.com` and `ns2.dns-parking.com`.)*
3. **Delete** any existing `A` record for `@` and any `CNAME` for `www` — usually
   Hostinger's parking page. Leave MX records alone if you use email on the domain.
4. Add the root record:

   | Field | Value |
   |---|---|
   | Type | `A` |
   | Name | `@` |
   | Points to | the IP Render showed you |
   | TTL | `3600` |

5. Add the www record:

   | Field | Value |
   |---|---|
   | Type | `CNAME` |
   | Name | `www` |
   | Points to | `swacchokhan.onrender.com` (Render's exact hostname, with the trailing dot if Hostinger adds one) |
   | TTL | `3600` |

6. Save. Hostinger usually propagates in 15–60 minutes; allow up to 24 hours.

Render detects the change, verifies the domain and issues a free Let's Encrypt
certificate automatically. The Custom Domains page shows a green tick when it's done.

---

## Step 5 — Set SITE_ORIGIN and redeploy

Once the domain resolves, go to **Render → Environment** and set:

```
SITE_ORIGIN=https://swacchokhan.space
```

Then **Manual Deploy → Deploy latest commit**.

This matters more than it looks. Without it, canonical URLs, `sitemap.xml` and your
social preview images all follow whatever hostname the request arrived on — which
splits your SEO between `swacchokhan.onrender.com` and your real domain, and Google
treats them as duplicate sites.

## Step 6 — Verify the live site

Check these on the real domain:

- [ ] `https://swacchokhan.space` loads and redirects from `http://`
- [ ] `www` reaches the same site
- [ ] The 3D book opens on `/journey`
- [ ] The assistant answers "how do I contact him"
- [ ] **Send yourself a message through `/contact`** and confirm it arrives in Gmail
- [ ] `/sitemap.xml` shows `https://swacchokhan.space/...`, not `.onrender.com`
- [ ] Paste the URL into <https://www.linkedin.com/post-inspector/> — the preview
      card should show your name over the gradient

---

## Step 7 — Tell Google it exists

This is the part that actually decides whether anyone in Bangladesh finds you.

1. <https://search.google.com/search-console> → add `https://swacchokhan.space` as a
   **Domain** property. It asks for a TXT record — add it in the same Hostinger DNS
   page as before.
2. **Sitemaps → Submit** `https://swacchokhan.space/sitemap.xml`
3. **URL Inspection** on the homepage → **Request indexing**.
4. Add the site to your LinkedIn profile and your GitHub profile README, and link it
   from `websthan.online`. Real inbound links move Bangladesh rankings far more than
   any meta tag.

Expect a week or two before you rank for "Swaccho Khan", longer for competitive
terms like "web developer Dhaka".

## Updating the site later

```bash
git add -A && git commit -m "Update copy" && git push
```

Render rebuilds and redeploys automatically. Most content changes only need
`data/profile.json` — no code, no rebuild logic to think about.

If you change your name, role or city, also run `npm run og` and commit the new
`public/img/og.jpg` so the social card matches.

## Other free hosts

If Render's cold start bothers you, the app is a plain Node/Express server with no
platform-specific code — it runs anywhere with `npm install && npm start`:

- **Koyeb** — free tier, historically without sleep. Same DNS steps.
- **Fly.io** — generous but wants a card on file.
- **Oracle Cloud Free Tier** — a genuinely always-free VM, but you administer the
  whole box yourself (Node, nginx, certbot, firewall).

**Not suitable:** Vercel, Netlify and Cloudflare Pages are serverless. The app would
run, but the in-memory rate limiter and the GitHub cache reset on every cold
invocation, which weakens two of the security layers. Use a real server.
